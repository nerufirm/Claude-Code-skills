## 1. このダッシュボードが解く課題

朝イチ／移動中に「これさえ見れば一日が回る」状態を作る。情報が Gmail・Slack・Notion・カレンダー・スプレッドシート・外部（天気/株価）に散らばっているのを、**1画面に集約**して「見逃し」と「探す手間」をゼロにする。

---

## 2. 確定した要件（グリルの結果）

| 項目 | 決定 | 備考 |
|---|---|---|
| 置き場所 | **Vercel の自分専用 Web アプリ** | Next.js（App Router）、レスポンシブ |
| 利用シーン | **PC・スマホ両方** | モバイルファーストのレイアウト |
| 鮮度 | **数分おきに自動更新** | クライアントポーリング（SWR） |
| アクセス制御 | **Google ログイン必須** | `sato@nerufirm.com` のみ許可（allowlist） |
| KPI の源 | **Google スプレッドシート（Drive）** | 一部はあとで追加（拡張可能に） |

### 表示したいもの（主目的・全部のせ）
1. **今日の予定** — Google カレンダー
2. **天気** — 現在＋本日の予報（都市は要指定）
3. **株価** — ウォッチリストの推移（銘柄は要指定）
4. **KPI / 数字のモニタリング** — Google スプレッドシート由来、トレンド付き
5. **通知の集約（見逃し防止）** — Gmail（重要/未読・要返信）＋ Slack（メンション/未読）
6. **プロジェクト/仕事の進捗** — Notion データベース（ステータス別・締切間近）

---

## 3. 重要な前提（ここは誤解しやすいので明記）

このセッションに繋がっている MCP（Gmail / Slack / Notion / カレンダー / Drive / Supabase / Vercel）は、**私が開発・テストするためのもの**です。
デプロイされた Vercel アプリが実行時にデータを取りに行くには、**アプリ自身の API 認証情報**（各サービスの OAuth アプリ / サービスアカウント / トークン）が別途必要になります。

→ つまりダッシュボードは「MCP に相乗りする」のではなく、**各サービスの API を直接叩く独立アプリ**として作ります。秘密情報はすべて Vercel の環境変数に格納し、**サーバー側（API Route）でのみ**使用します（ブラウザには出しません）。

## 4. アーキテクチャ

```
┌──────────────────────────── Browser (PC / スマホ) ────────────────────────────┐
│  Next.js フロント（レスポンシブ・グリッド）                                     │
│   各ウィジェットが SWR で数分おきにポーリング                                   │
└───────────────┬───────────────────────────────────────────────────────────────┘
                │  fetch /api/*
┌───────────────▼─────────────── Next.js API Routes（サーバー側）────────────────┐
│  /api/calendar   /api/weather   /api/stocks                                     │
│  /api/kpi        /api/notifications（gmail+slack）  /api/projects（notion）     │
│   - 認証ガード（ログイン必須・allowlist）                                       │
│   - 各サービスの秘密情報はここでのみ使用                                        │
│   - レート制限回避のため短期サーバーキャッシュ（revalidate）                    │
└──┬─────────┬─────────┬──────────┬───────────┬───────────────┬──────────────────┘
   │         │         │          │           │               │
 Google   Weather   Stock      Google      Gmail API       Notion API
 Calendar  API       API       Sheets      Slack API
   API                          API
```

### 技術スタック
- **Next.js 15（App Router）/ TypeScript** — API Route で秘密情報をサーバー側に隔離できる
- **Tailwind CSS + shadcn/ui** — レスポンシブなカードUIを素早く
- **Recharts** — KPI のトレンド・株価のミニチャート
- **SWR** — `refreshInterval` で数分おき自動更新（ソースごとに間隔を調整）
- **Auth.js (NextAuth)** — Google ログイン＋ allowlist
- **デプロイ: Vercel** — 環境変数で各 API キーを管理

## 6. ウィジェット仕様

| ウィジェット | データ源 | API Route | 更新間隔(目安) | 表示内容 |
|---|---|---|---|---|
| 今日の予定 | Google Calendar API | `/api/calendar` | 5分 | 本日のイベント（開始時刻・タイトル・場所/リンク） |
| 天気 | 外部天気API（例: Open-Meteo＝無料・キー不要） | `/api/weather` | 10分 | 現在気温/天気＋本日の最高/最低・降水 |
| 株価 | 株価API（候補は §8 参照） | `/api/stocks` | 1〜5分 | 銘柄ごと現在値・騰落率・当日ミニチャート |
| KPI | Google Sheets API | `/api/kpi` | 5分 | 主要数字・前回比・スパークライン |
| 通知 | Gmail API ＋ Slack API | `/api/notifications` | 3〜5分 | 重要/未読件数・要返信リスト・メンション |
| 進捗 | Notion API | `/api/projects` | 10分 | ステータス別件数・締切間近・担当ビュー |

> SWR の `refreshInterval` をウィジェット単位で設定。株価だけ短く、進捗は長く。
> サーバー側は `Cache-Control` / `revalidate` で短期キャッシュし、API レート制限を回避。

## 7. セキュリティ / プライバシー（「私専用」の守り方）

- **Google ログイン必須**（Auth.js Google Provider）
- `signIn` コールバックで **`sato@nerufirm.com` のみ許可**（allowlist）。それ以外は拒否。
- **middleware** で全ページ・全 API Route を保護（未認証はログインへリダイレクト/401）
- API キー・トークンは **Vercel 環境変数**のみ。クライアントへは一切渡さない（`NEXT_PUBLIC_` を付けない）
- 各サービス連携は**読み取り権限（read-only スコープ）**に限定

## 8. 着手前に決める「中身」の具体（オープン項目）

設計の骨は固まりました。実装前にこの中身だけ埋めれば即着手できます：

1. **株価の銘柄** — 例: `AAPL, GOOGL, 7203.T(トヨタ)` など。何を並べる？
   - 併せて株価APIの選定（無料枠: Finnhub / Alpha Vantage / Twelve Data 等。レート制限と日本株対応で選ぶ）
2. **天気の都市** — 例: 東京。複数表示する？
3. **KPI スプレッドシート** — 対象シートのURL、どのセル/列が何の指標か（指標名・単位・「前日比」の取り方）
4. **通知の対象**
   - Gmail: どのラベル/条件を「重要・要返信」とみなす？
   - Slack: 監視するチャンネル or メンションのみ？
5. **Notion 進捗** — 対象データベース、ステータスのプロパティ名、「締切」プロパティ名

## 9. 実装ロードマップ（設計承認後）

- **フェーズ0 — 土台**: Next.js + Tailwind + Auth.js（Google ログイン＋allowlist）。空のダッシュボード枠＋レスポンシブグリッド。Vercel に初回デプロイ。
- **フェーズ1 — 外部だけで動く実感**: 天気・株価（外部APIのみ＝認証連携不要）を先に実装。「数分おき更新」の体験を確立。
- **フェーズ2 — 自分のデータ**: カレンダー → KPI(Sheets) → 通知(Gmail/Slack) → 進捗(Notion) を1つずつ追加。
- **フェーズ3 — 仕上げ**: 最終更新時刻表示・手動リフレッシュ・エラー時のフォールバック表示・モバイル微調整。

各フェーズ末でデプロイし、スマホ実機で確認しながら進めます。
