# 議論ガイド（60〜90分セッション）

本稿を経営チーム・事業責任者・組織開発チームで議論するためのファシリテーションガイド。

## 想定する場

- 経営合宿・経営会議の1セッション
- 事業部の年次オフサイト
- 人事・組織開発チームの戦略議論
- AI推進タスクフォースのキックオフ

## 推奨参加者

4〜10名。経営者・事業責任者・人事・財務・AI/DX推進が混在することが理想。1人だけの専門領域に閉じない構成にする。

## 事前準備（参加者）

- [summary.md](./summary.md) の10分版を読了
- [executive-questions.md](./executive-questions.md) の20問に各自で◎/○/△を付けてくる

## セッション構成（90分版）

### Part 1：認識合わせ（15分）

ファシリテーターが要約を5分で口頭プレゼン。「3市場 × 3変化 = 9つ」「9変化を貫く1つの問い」を黒板/ホワイトボードに書き出す。

質問タイム10分。「この枠組み自体に違和感はあるか？」を最初に確認する。違和感を抑えずに出してもらうほど後の議論が深まる。

### Part 2：自社診断の照合（25分）

事前に各自が付けた◎/○/△を持ち寄り、20問それぞれについて参加者のスコアを並べる（付箋・スプレッドシート等）。

ファシリテーターは**スコアが割れた問い**を3〜5問選ぶ。

- 「同じ会社を見ているのにスコアが割れる」＝認識のずれ＝重要な戦略論点
- 1問あたり5分、当事者の認識を聞き出す

このパートのゴールは合意ではなく、**「我々はこの問いについて共通言語を持っていない」と気づくこと**。

### Part 3：1つの問いを選ぶ（10分）

9つの変化の中から、自社にとって**最も重要かつ最も着手できていない1つ**を選ぶ。

選定基準：

1. 影響の大きさ（放置すると致命的か）
2. 着手の遅れ（競合・他社に対して遅れているか）
3. 着手可能性（半年〜1年で動かせるか）

投票で1つに絞る。複数選びたい誘惑に抗うのがコツ。**1つに集中する勇気がない経営は、9つすべてに対応できない**。

### Part 4：「貫く問い」への変換（25分）

選んだ1つの変化を、本稿の「貫く問い」のフォーマットに置き換える。

> AIをどう組織に設計・統合し、自社固有の[___]をどう蓄積するか。

[___] に入る自社固有の資産・能力・関係を具体的に言語化する。

例：

- 「自社固有の**顧客との対話履歴と暗黙のニーズ理解**をどう蓄積するか」
- 「自社固有の**製造現場の意思決定パターン**をどう蓄積するか」
- 「自社固有の**業界内の信頼関係とアルムナイネットワーク**をどう蓄積するか」

抽象論で終わらせず、**1つの具体名詞**に落とすことが重要。

### Part 5：次の90日のアクション（15分）

選んだ1問について、次の90日で動かす3つのアクションを決める。

- 何を（具体的な意思決定 or 取り組み）
- 誰が（オーナー1名を明記）
- いつまでに（期日）
- 何を持って前進と判断するか（観察可能な指標）

アクションは**3つまで**に絞る。9変化の全方位対応は失敗の原因。

## ファシリテーターへの注意

### よくある失敗パターン

1. **9つすべてに対応しようとする**
   - 全方位対応は実質的な「何もしない」と同じ。1つに絞る勇気を支援する。

2. **AIツールの話に流れる**
   - 「どのツールを使うか」の議論に流れたら、「本稿の主題はその外側」と引き戻す。

3. **抽象論で終わる**
   - 「我が社の固有性は信頼です」のような言葉で終わらせない。「**どのような場面で、誰に対する、どのような形の信頼か**」を具体化する。

4. **経営者だけが話す**
   - 9変化は事業・人事・財務・AI推進が連動する話。経営者の独白で終わらせず、各専門領域からの反応を引き出す。

5. **二項対立で考える**
   - 「AIか人か」「効率か固有性か」ではない。「**どの機能をどう組み合わせるか**」の設計問題として扱う。

### 議論を深めるための問い

- 「この変化に対応しなかった場合、5年後に何が起きるか？」
- 「この変化に最も先に対応した場合、競合に対してどんな差ができるか？」
- 「我が社で、この変化を最も実感している人は誰か？　次の議論にその人を呼ぶべきではないか？」
- 「この問いに対する答えを持っている人が社外にいるとしたら、それは誰か？」
